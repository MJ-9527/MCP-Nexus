# 角色 B：网关、安全与调用代理

## 负责范围

负责 MCP 工具发现、调用转发、JWT、RBAC、Redis 限流、统一错误、审计埋点和网关可靠性。

## 主要目录

`client/`、`middleware/`、`service/`、`handler/`、`router/`、`metrics/`

## 第 1 周

### B1：建立 MCP 网关路由

- 增加 `GET /mcp/tools` 与 `POST /mcp/tools/:toolName/call`。
- 让路由通过 service 查询注册中心，不直接访问数据库。
- 完成标准：请求可进入统一网关调用链。

### B2：实现下游 MCP HTTP Client

- 支持 Streamable HTTP JSON 请求、响应透传、连接复用和 Header 传递。
- 设置默认请求超时和响应体大小限制。
- 完成标准：可调用示例服务的 `query_sales`。

### B3：实现工具发现与调用前检查

- 查询 Tool、Server，检查 published、active 和 online 状态。
- 对不存在、下线、离线工具返回明确业务错误。
- 完成标准：发现列表只包含当前可调用工具。

### B4：统一错误与请求上下文

- 定义 `TOOL_NOT_FOUND`、`TOOL_OFFLINE`、`SERVER_UNAVAILABLE`、`UPSTREAM_TIMEOUT`、`UPSTREAM_ERROR`。
- 传递 `request_id`，统一 JSON 错误结构和超时处理。
- 完成标准：所有失败场景状态码和响应格式稳定。

## 第 2 周

### B5：实现 JWT 认证中间件

- 校验签名、过期时间、用户 ID 和角色。
- 从 Authorization Header 读取 Bearer Token，并注入请求上下文。
- 完成标准：缺失、伪造、过期 Token 返回 `401`。

### B6：实现 RBAC 与工具权限校验

- 根据用户/角色和 Tool 权限执行调用前授权。
- 区分查看、调用、发布和管理等操作权限。
- 完成标准：无权限调用返回 `403`，并保留拒绝原因。

### B7：接入 Redis 令牌桶限流

- 设计按用户、角色或工具的限流 Key 和窗口策略。
- Redis 不可用时按约定返回错误或降级，并记录日志。
- 完成标准：超过阈值返回 `429`，正常请求不被误拒绝。

### B8：接入审计埋点与安全错误处理

- 记录成功、失败、拒绝、限流请求的调用者、工具、耗时和状态。
- 脱敏参数，不记录 Token、密钥和明文敏感值。
- 完成标准：每次调用都有可追踪审计事件。

## 第 3 周

### B9：生成 MCP 接入配置

- 根据工具详情生成网关地址、工具名、认证方式和环境变量模板。
- 处理配置字段缺失和版本选择。
- 完成标准：前端复制的配置可用于接入网关。

### B10：对接 OpenAPI 包装器

- 接入包装器生成的 Server、Tool 和调用地址。
- 透传 API Key/Bearer Token 的安全引用，不打印密钥。
- 完成标准：生成工具可通过统一网关调用。

### B11：对接 Skills 适配器

- 接入 Skills 适配任务生成的工具描述、Schema 和 Endpoint。
- 统一适配器工具的发布、健康和权限检查。
- 完成标准：Skills 示例可以被发现并调用。

### B12：增加参数与版本校验

- 在转发前校验输入 Schema、必填参数和工具版本。
- 对校验失败返回明确错误，不发送下游请求。
- 完成标准：非法参数可预测地返回 `400` 类错误。

## 第 4 周

### B13：增强超时、重试与熔断

- 区分连接、请求和整体调用超时。
- 对幂等请求执行有限重试，对连续失败服务触发熔断。
- 完成标准：上游故障不会长期占用网关资源。

### B14：优化审计写入与可观测性

- 使用异步队列或批量方式写入 ClickHouse。
- 增加调用耗时、成功率、P95/P99 和上游状态指标。
- 完成标准：审计延迟不阻塞主调用，指标可被统计接口使用。

### B15：执行网关压测与性能优化

- 编写并执行工具发现、成功调用、拒绝调用和超时场景压测。
- 优化 HTTP Client、连接池、序列化和中间件开销。
- 完成标准：记录吞吐、P95/P99、环境和硬件限制。

### B16：完成安全调用演示链路

- 串联登录、工具发现、授权调用、脱敏数据返回和审计查询。
- 验证敏感工具拒绝、限流和上游故障场景。
- 完成标准：完整链路可重复演示并产生正确审计数据。

## 角色最终验收标准

- 所有 Agent 工具调用都经过认证、权限、限流、健康检查和审计。
- 网关不绕过 Repository，不直接操作业务数据库。
- 上游异常、超时和拒绝场景均有稳定错误码和可观测记录。

## 依赖与交接

- 依赖 A 提供 Tool/Server/权限/审计 Repository 或 service 接口。
- 依赖 C 提供健康的示例服务、Redis、ClickHouse 和适配器示例。
- 为 D 提供路由、错误码、认证方式和压测结果。
