# 角色 D：前端、测试、文档与集成

## 负责范围

负责 React 工具市场、接口契约、自动化测试、README、联调、回归和最终交付材料。

## 主要目录

`web/` 或 `frontend/`、`tests/`、`does/`、`README.md`

## 第 1 周

### D1：整理 API 契约

- 整理 Server、Tool、健康检查和 MCP 网关的 OpenAPI 文档。
- 固化请求、响应、错误码、状态码和 `request_id` 字段。
- 完成标准：文档路径和字段与后端实现一致。

### D2：编写接口示例与联调脚本

- 提供 PowerShell、Postman 或 Go 脚本，覆盖注册、查询、发布和调用。
- 为成功、参数错误、资源不存在补充请求与响应示例。
- 完成标准：新成员可直接执行脚本验证接口。

### D3：更新启动与开发文档

- 更新 README 的环境要求、`.env`、Compose、迁移和服务启动说明。
- 记录 Windows PowerShell 与 GoLand 终端的调用方式差异。
- 完成标准：文档命令可在干净环境执行。

### D4：完成第一周端到端测试

- 验证注册 Server → 注册 Tool → 健康检查 → 发布 → 发现 → 调用。
- 保存测试结果并记录阻塞问题和接口偏差。
- 完成标准：最小闭环可重复通过。

## 第 2 周

### D5：实现 React 登录页面

- 实现用户名密码登录、Token 保存、退出和登录态恢复。
- 避免将 Token 放入 URL、页面明文或错误日志。
- 完成标准：合法用户可登录，非法登录展示统一错误。

### D6：实现请求拦截与受保护路由

- 为 API 请求自动添加 Bearer Token。
- 处理 `401` 跳转登录、Token 过期和网络错误。
- 完成标准：受保护页面和接口请求行为一致。

### D7：实现工具列表与详情基础页面

- 展示搜索结果、发布状态、健康状态、版本和输入 Schema。
- 接入工具列表、详情和基础筛选 API。
- 完成标准：页面不直接访问下游 MCP Server。

### D8：补充安全场景回归测试

- 覆盖无权限 `403`、限流 `429`、未登录 `401` 和上游错误。
- 验证错误消息、request ID 和页面反馈一致。
- 完成标准：关键安全场景都有自动化或可重复脚本。

## 第 3 周

### D9：完善工具市场浏览体验

- 增加分类、标签、关键词搜索、筛选、排序和分页。
- 处理加载中、空数据、接口失败和重试状态。
- 完成标准：用户可以快速找到已发布工具。

### D10：实现评分、评论与工具详情

- 展示平均评分、评论列表、提交评论和重复评分提示。
- 在详情页展示 Server、版本、健康和 Schema 信息。
- 完成标准：市场详情数据与 A 的接口一致。

### D11：实现接入配置与 OpenAPI 入口

- 增加一键复制 MCP 配置、OpenAPI 文件导入和任务状态展示。
- 展示处理中、成功和失败结果及错误原因。
- 完成标准：生成配置可复制，导入流程状态清晰。

### D12：实现 Skills 适配入口与联合联调

- 增加 Skills 上传/选择、适配任务和生成工具展示。
- 与 A、B、C 联调注册、发布、发现和调用。
- 完成标准：OpenAPI/Skills 生成工具可从前端进入统一调用链。

## 第 4 周

### D13：实现统计 Dashboard

- 展示总调用、调用趋势、Top 工具、成功率和失败率。
- 提供空数据、加载、时间范围和接口错误状态。
- 完成标准：Dashboard 字段与统计 API 一致。

### D14：实现告警展示与确认

- 展示拒绝调用、异常高频调用和告警状态。
- 支持查看详情、确认和已处理状态。
- 完成标准：告警状态变更可回写并可追踪。

### D15：执行全量回归与兼容性验证

- 执行 Go 测试、接口回归、端到端、前端构建和主要浏览器检查。
- 验证干净环境、已有数据、权限拒绝和上游故障场景。
- 完成标准：输出测试报告、失败项和已知限制。

### D16：完成发布文档与最终验收

- 汇总部署文档、压测报告、答辩材料、演示脚本和截图。
- 按最终链路执行验收并记录版本、配置和提交信息。
- 完成标准：新成员可按文档复现完整演示。

## 角色最终验收标准

- 前端覆盖登录、工具市场、接入配置、统计和告警主要流程。
- API 契约、测试脚本、README 与实际代码保持一致。
- 关键成功、错误、安全和故障场景均有测试证据。

## 依赖与交接

- 依赖 A 提供稳定数据接口和字段文档，依赖 B 提供认证/网关契约。
- 依赖 C 提供 Compose、演示数据、OpenAPI/Skills 示例和环境说明。
- 最终负责汇总各角色测试结果，但不修改其他角色的业务实现来掩盖失败。
