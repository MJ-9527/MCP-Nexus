# 企业级 MCP 工具市场与智能体网关

## MVP 开发需求文档

### 1. 项目概述

本项目建设一个面向企业内部 AI Agent 的 MCP 工具市场与智能体网关，统一管理 MCP Server 和工具，提供工具发现、权限控制、调用代理、限流、审计和基础统计能力。

项目定位为比赛答辩 MVP，优先完成可稳定演示的安全调用闭环。

### 2. 目标与核心场景

#### 2.1 项目目标

- 统一注册和管理企业 MCP Server。
- 为 Agent 提供统一的 MCP 工具调用入口。
- 实现 JWT 认证、RBAC 鉴权、限流和审计。
- 提供可浏览、搜索和接入的工具市场。
- 支持限定 OpenAPI 子集自动生成 MCP 工具骨架。

#### 2.2 主演示场景

Agent 通过网关查询内置脱敏业务数据库并生成报表，同时展示：

1. Agent 登录认证。
2. 工具发现与接入配置生成。
3. 授权工具调用。
4. 敏感工具无权限拒绝。
5. 调用日志与审计统计。

### 3. 用户角色与权限

系统采用单租户和三角色模型。

| 角色 | 主要权限 |
|---|---|
| 平台管理员 | 用户管理、工具审核、发布/下线、权限配置、审计查看、统计查看 |
| 工具开发者 | 注册 MCP Server、维护工具信息、提交发布、查看自身工具调用数据 |
| Agent 调用者 | 浏览工具、搜索工具、获取接入配置、调用已授权工具、评分评论 |

权限控制关系：角色 → 工具权限 → 操作权限。

必须支持的操作权限：

- 查看工具
- 调用工具
- 注册和编辑工具
- 发布和下线工具
- 配置工具权限
- 查看审计日志
- 评分和评论

### 4. 功能需求

#### 4.1 用户认证

- 提供用户名密码登录接口。
- 登录成功后签发 JWT。
- JWT 至少包含用户 ID、角色和过期时间。
- 密码必须使用安全哈希保存。
- 缺失、伪造或过期 Token 必须拒绝请求。
- 所有受保护接口返回统一错误格式。

#### 4.2 MCP Server 注册中心

- 注册 MCP Server 名称、地址、描述、负责人和版本。
- 维护 MCP Server 的发布状态和健康状态。
- 同步和保存 MCP 工具清单。
- 保存工具名称、描述、分类、标签、输入 Schema 和版本。
- 支持工具发布、下线和版本更新。
- 定时或按需执行健康检查。
- 对离线或未发布工具禁止调用。

MVP 仅支持 Streamable HTTP 传输，不要求支持 stdio 和 SSE。

#### 4.3 智能体网关

网关是所有 Agent 工具调用的统一入口。

处理流程：

1. 校验 JWT。
2. 校验调用者角色和工具权限。
3. 校验工具是否已发布且健康。
4. 执行限流策略。
5. 转发 MCP 工具调用。
6. 返回工具结果或标准化错误。
7. 记录调用审计信息。

核心接口：

- `GET /mcp/tools`：获取当前可用工具列表。
- `POST /mcp/tools/{toolName}/call`：调用指定工具。
- `GET /health`：网关健康检查。

#### 4.4 限流与错误处理

- 使用 Redis 实现令牌桶限流。
- 支持按用户、角色或工具设置调用频率。
- 超过限制时返回 HTTP 429。
- MCP Server 超时、不可达或异常时返回统一错误。
- 每个请求生成唯一 `request_id`。

#### 4.5 工具市场

前端必须提供：

- 工具分类浏览：数据库、办公、研发、营销等。
- 关键词搜索。
- 工具详情页。
- 工具版本、健康状态和输入 Schema 展示。
- 评分和评论。
- 调用量排行。
- 一键生成 MCP 接入配置片段。
- 管理员工具审核、发布和下线入口。

市场不直接执行工具，所有调用必须经过网关。

#### 4.6 OpenAPI 自动包装器

MVP 支持以下 OpenAPI 子集：

- OpenAPI 3.x JSON 或 YAML 文件。
- GET、POST 方法。
- Path、Query、Header、Body 基础参数。
- API Key 和 Bearer Token。
- 基础响应 Schema。

生成结果必须包括：

- MCP 工具名称和描述。
- 输入参数 Schema。
- Go 或 TypeScript MCP Server 骨架。
- 环境变量配置模板。
- Dockerfile。
- 启动说明。

不支持的 OpenAPI 特性必须返回明确错误，不得静默生成错误代码。

#### 4.7 Skills 适配器

- 提供规范化 Skills 转 MCP 工具的转换接口。
- 至少提供一个可运行示例。
- 不要求实现完整 Skills 运行时生态。

#### 4.8 审计与统计

每次调用至少记录：

- `request_id`
- 调用者 ID 和角色
- 工具名称和 Server ID
- 参数摘要
- 调用时间
- 耗时
- 成功或失败状态
- HTTP 状态码
- 拒绝原因
- 估算成本

敏感参数不得明文写入日志，只保存脱敏结果或摘要。

统计页面至少展示：

- 总调用次数
- 工具调用趋势
- Top 工具排行
- 成功率和失败率
- 拒绝调用次数
- 敏感工具异常高频调用告警

### 5. 数据需求

使用 PostgreSQL 保存业务数据，Redis 保存缓存和限流状态，ClickHouse 保存调用日志分析数据。

核心数据实体：

- 用户 `users`
- 角色 `roles`
- MCP Server `mcp_servers`
- MCP 工具 `mcp_tools`
- 工具版本 `tool_versions`
- 工具权限 `tool_permissions`
- 评分评论 `reviews`
- 审计日志 `audit_logs`

演示环境必须内置脱敏业务数据库和固定初始化数据。

### 6. 技术要求

- 后端：Go + Gin 或 Echo。
- MCP：MCP Go/TypeScript SDK 1.x。
- 传输：Streamable HTTP。
- 前端：React 19 + TypeScript。
- 数据库：PostgreSQL。
- 缓存与限流：Redis。
- 日志分析：ClickHouse。
- 链路追踪：OpenTelemetry。
- 部署：Docker Compose。
- API：提供 OpenAPI 3.0 接口文档。
- 配置：提供 `.env.example`。
- 错误格式统一为：`code`、`message`、`request_id`。

### 7. 核心 API

- `POST /api/auth/login`
- `GET /api/tools`
- `POST /api/tools`
- `GET /api/tools/{id}`
- `POST /api/tools/{id}/publish`
- `POST /api/tools/{id}/permissions`
- `POST /api/openapi/import`
- `GET /api/audit/logs`
- `GET /api/analytics/overview`
- `GET /mcp/tools`
- `POST /mcp/tools/{toolName}/call`

### 8. 团队分工

#### 后端开发一：网关与安全

负责 MCP 代理、JWT、RBAC、Redis 限流、统一错误处理和审计埋点。

#### 后端开发二：注册中心与数据服务

负责数据库模型、MCP Server 注册、工具管理、健康检查、市场 API 和日志写入。

#### 前端开发：工具市场

负责登录、工具列表、搜索、详情、评分、接入配置和统计页面。

#### 架构/测试/整合

负责接口规范、OpenAPI 包装器、示例 MCP Server、Docker Compose、压测、联调和交付文档。

### 9. 开发计划

#### 第 1 周：基础架构

- 确定 API 和数据模型。
- 完成网关代理骨架。
- 完成注册中心和数据库初始化。
- 实现工具列表和健康检查。

#### 第 2 周：安全闭环

- 完成 JWT 登录。
- 完成 RBAC 鉴权。
- 完成 Redis 限流。
- 完成审计日志。
- 接入数据库、文件、HTTP 三个示例工具。

#### 第 3 周：市场与自动包装

- 完成工具市场前端。
- 完成搜索、详情、评分和接入配置。
- 完成限定版 OpenAPI→MCP 生成器。

#### 第 4 周：交付与验收

- 完成统计和告警页面。
- 完成压测和性能优化。
- 完成 Agent 查库生成报表演示。
- 完成 Docker Compose、部署文档和答辩材料。

### 10. 验收标准

- 合法用户可以登录并调用已授权工具。
- 无权限 Agent 调用敏感工具时 100% 被拒，并生成审计记录。
- JWT 缺失、伪造或过期时请求被拒绝。
- 限流超过阈值时返回 HTTP 429。
- 未发布或不健康工具不可调用。
- OpenAPI 示例文档能够生成可运行 MCP Server 骨架。
- Agent 能完成“查询数据库→生成报表”完整任务。
- 网关额外转发开销目标为 P99 小于 5ms。
- 测试环境目标吞吐不低于 2000 QPS；如受硬件限制，须记录实际结果。
- Docker Compose 一键启动后，核心服务健康检查通过。

### 11. MVP 不包含内容

- 多租户和组织隔离。
- stdio、SSE 等其他 MCP 传输方式。
- 完整 OpenAPI 3.x 特性覆盖。
- Kubernetes、高可用集群和服务网格。
- 商业计费结算。
- 复杂工作流编排。
- 生产级密钥托管。
- 完整 Skills 运行时生态。
