# 变量命名与合并规范

## 目的

统一 A/B/C/D 分支合并时的字段、环境变量、JSON 参数和数据库列名，避免同一概念出现多套名称。

## 命名规则

- Go：导出类型使用 `PascalCase`，局部变量使用 `camelCase`。
- JSON：统一使用 `snake_case`，例如 `page_size`、`tool_id`、`sensitive_level`。
- PostgreSQL：表名和列名使用小写 `snake_case`。
- 环境变量：使用全大写 `UPPER_SNAKE_CASE`，并同步更新 `.env.example`。
- 路由参数保持资源语义一致：工具使用 `:id`，适配任务使用 `:task_id`。
- 状态值必须使用文档定义的小写枚举：`pending`、`running`、`success`、`failed`。
- 角色名统一使用：`platform_admin`、`tool_developer`、`agent_caller`。

## 合并前检查

新增字段或变量时，必须同时检查并更新：

1. Go model、Repository、Service、Handler。
2. JSON 请求/响应字段和 API 文档。
3. PostgreSQL migration 与查询字段。
4. `.env.example`（如果是环境变量）。
5. 本文“变量登记表”。
6. 至少一个参数校验或接口测试。

## 变量登记表

| 名称 | 类型/位置 | 用途 |
|---|---|---|
| `tool_id` | JSON/数据库 | MCP 工具唯一标识 |
| `task_id` | 路由/JSON | 适配任务唯一标识 |
| `task_type` | JSON/数据库 | `openapi_import` 或 `skills_adaptation` |
| `status` | JSON/数据库 | 适配任务状态 |
| `source_url` | JSON/数据库 | OpenAPI 或 Skills 来源地址 |
| `error_message` | JSON/数据库 | 失败原因 |
| `page_size` | 查询参数 | 分页大小，最大 100 |
| `JWT_SECRET` | 环境变量 | JWT 签名密钥 |
| `JWT_TTL` | 环境变量 | JWT 有效期 |
| `REDIS_ADDR` | 环境变量 | Redis 地址 |
| `PUBLIC_BASE_URL` | 环境变量 | 对外网关地址 |
| `CLICKHOUSE_ADDR` | 环境变量 | ClickHouse HTTP 地址，例如 `localhost:8123` |
| `CLICKHOUSE_DATABASE` | 环境变量 | ClickHouse 数据库名 |
| `CLICKHOUSE_USER` | 环境变量 | ClickHouse 用户名 |
| `CLICKHOUSE_PASSWORD` | 环境变量 | ClickHouse 密码 |

后续开发新增变量名时，必须在本文件登记，并同步修改 API 文档、migration 或 `.env.example`（按变量所属层级）。
