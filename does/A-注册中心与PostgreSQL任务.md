# 角色 A：注册中心与 PostgreSQL 数据服务

## 负责范围

负责业务数据模型、PostgreSQL 持久化、Server/Tool 注册中心、工具市场数据、权限数据和统计数据接口。

## 主要目录

`model/`、`repository/`、`service/`、`handler/`、`router/`、`config/`、`db/migrations/`

## 第 1 周

### A1：确定核心数据模型

- 定义 `mcp_servers`、`mcp_tools` 字段、状态枚举、外键关系和时间字段。
- 增加名称、Endpoint、Server-Tool 组合唯一约束及常用索引。
- 完成标准：模型与第一周 API 文档一致，重复数据可被数据库拒绝。

### A2：完成 PostgreSQL 初始化与连接池

- 编写迁移脚本、数据库 DSN 配置、连接池初始化和 `.env.example`。
- 处理连接失败、关闭连接池和启动时健康检查。
- 完成标准：Docker PostgreSQL 启动后，服务可连接并执行迁移。

### A3：实现 Server/Tool Repository

- 实现 Server、Tool 的创建、列表、详情、更新和状态变更方法。
- 统一 `context.Context`、NotFound、冲突和数据库错误映射。
- 完成标准：Repository 不依赖内存存储，单元测试覆盖成功和失败场景。

### A4：完成注册中心 API

- 接通 Server/Tool service、handler 和路由。
- 实现注册、查询、发布、下线和健康状态持久化。
- 完成标准：注册后重启服务仍能查询；重复 Server/Tool 返回 `409`。

## 第 2 周

### A5：建立用户和角色数据

- 增加 `users`、`roles` 及用户角色关联模型和迁移。
- 提供按用户名查询用户、密码哈希和角色的方法。
- 完成标准：登录服务可以从 PostgreSQL 读取用户和角色。

### A6：实现工具权限 Repository

- 增加 `tool_permissions` 表及授权、撤销、查询方法。
- 支持用户、角色与工具操作权限的关联。
- 完成标准：能判断指定主体是否拥有某工具的调用权限。

### A7：实现权限管理 API

- 编写权限配置、查询、删除 service、handler 和路由。
- 校验 Tool、用户、角色存在性和重复授权。
- 完成标准：管理员可配置权限，非法主体或重复授权返回明确错误。

### A8：实现审计日志数据服务

- 增加 `audit_logs` 表、写入 Repository 和分页查询接口。
- 保存 request ID、调用者、工具、耗时、状态、拒绝原因和参数摘要。
- 完成标准：敏感参数不明文保存，成功、失败、拒绝请求均可查询。

## 第 3 周

### A9：扩展工具市场模型

- 增加分类、标签、版本、Schema、评分和评论相关表或字段。
- 增加唯一约束、外键和搜索索引。
- 完成标准：工具详情具备市场展示和接入配置所需数据。

### A10：实现工具搜索与筛选

- 支持关键词、分类、标签、状态、分页和排序查询。
- 限制分页大小并校验查询参数。
- 完成标准：市场列表结果稳定，空结果和非法参数有统一响应。

### A11：实现评分、评论与排行

- 提供评分、评论新增/查询及调用量排行接口。
- 防止同一用户重复评分，处理评论分页和敏感内容校验。
- 完成标准：详情页可取得平均评分、评论列表和排行数据。

### A12：实现工具详情与适配任务记录

- 聚合 Tool、Server、版本、健康状态和输入 Schema。
- 增加 OpenAPI 导入、Skills 适配任务及状态查询模型。
- 完成标准：适配任务具有 pending、running、success、failed 等可追踪状态。

## 第 4 周

### A13：设计 ClickHouse 审计存储

- 定义 ClickHouse 审计表、字段映射、写入批次和失败处理边界。
- 保留 PostgreSQL 业务审计查询所需的最小数据。
- 完成标准：审计数据可写入分析库，失败不会阻塞主调用链。

### A14：实现统计与告警 API

- 提供总调用、趋势、Top 工具、成功率、失败率和拒绝原因统计。
- 增加异常调用告警表、查询和确认状态接口。
- 完成标准：返回字段固定，可直接供 Dashboard 使用。

### A15：完成数据库性能与保留策略

- 检查关键查询索引、分页上限和慢查询。
- 制定审计数据保留、归档和清理策略。
- 完成标准：核心查询在演示数据量下无明显全表扫描。

### A16：完成迁移、Seed 与备份恢复验证

- 编写空库初始化、演示数据、备份和恢复文档。
- 执行清空数据库后的全量迁移和 Seed 验证。
- 完成标准：新环境可按文档恢复出可联调数据。

## 角色最终验收标准

- Server、Tool、用户、权限、审计和市场数据均持久化在规定数据库中。
- 关键 API 的错误码、分页和状态定义稳定。
- 数据库重启或服务重启不会丢失已确认数据。

## 依赖与交接

- 依赖 C 提供数据库容器、Redis/ClickHouse 容器和 Seed 运行环境。
- 为 B 提供稳定的 Repository 接口和权限/审计数据接口。
- 为 D 提供 OpenAPI 契约、字段说明和测试数据。
